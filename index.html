SFPS

부머 슈터 · 자체 엔진 C · 엔진 직접 구현

1.44MB 플로피 한 장에 들어가는 3D FPS. 단일 .exe이고 에셋 파일이 하나도 없습니다. 상용 엔진 없이 Win32와 OpenGL 3.3 코어만 써서 엔진부터 C로 직접 작성했습니다.

핵심 문제

1,474,560바이트 안에 게임 하나를 통째로 넣어야 했습니다. 답은 압축이 아니라 에셋을 파일이 아니라 텍스트 레시피로 두는 것이었습니다. 텍스처·모델·스프라이트·사운드가 전부 정수 텍스트로 기술돼 실행 시점에 생성됩니다. 모델은 2D 외곽선과 두께만 주면 엔진이 돌출시키고 귀 자르기로 삼각분할하며, UV는 그 과정에서 저절로 나와 언랩할 것이 없습니다. 현재 411,648 / 1,474,560 바이트로 예산의 27.9%를 씁니다.

CWin32 API OpenGL 3.3 CoreGLSL 절차적 생성핫 리로드

SRPG

실시간 전술 · Bad North 계열

계단식 대지와 초크포인트로 이루어진 섬에 상륙하는 적을 부대로 막아내는 실시간 전술 게임. 지형이 절차적으로 생성되고, 부대는 전투를 치를수록 성장합니다.

핵심 문제

전투 로직이 MonoBehaviour와 씬에 얽히면 규칙 하나를 검증할 때마다 게임을 켜야 합니다. 그래서 전투를 주문서를 받아 보고서를 내놓는 계약으로 정의하고, 판단 로직을 유니티에 의존하지 않는 순수 계층으로 내렸습니다. 어셈블리를 Core / Data / Systems / Gameplay / UI / Composition으로 갈라 의존 방향을 컴파일러가 강제하게 하고, VContainer로 전역 · 캠페인 · 전투 세 수명을 분리했습니다. 덕분에 전투 규칙을 EditMode 테스트로 씬 없이 돌립니다.

ASCIIROG

ASCII 로그라이크

@, #, . 문자로 그려지는 턴제 로그라이크. 고전 로그라이크 규칙 위에 물리·열역학 시뮬레이션 레이어를 얹었습니다.

핵심 문제

환경 상호작용을 정해진 연출로 재생하지 않습니다. 대신 모든 타일에 물질·상태·온도를 부여해 규칙끼리 부딪히게 했습니다. 불은 가연성 타일을 따라 번지고, 기름에 옮겨붙으면 폭발하며, 물은 얼거나 끓어 증기가 됩니다. 번개는 BFS로 전도성·젖은 타일을 타고 전파됩니다. 미리 설계하지 않은 조합까지 저절로 성립합니다.

RTXX

실시간 전략 · Total War 계열

부대 단위로 조작하는 RTS. 우클릭으로 선을 그어 부대의 정면과 폭을 지정하면 병사들이 해당 대형으로 정렬합니다. 2D 픽셀 스프라이트 병사가 3D 지형 위에서 전투합니다.

핵심 문제

병사 200명을 대형 슬롯 200개에 배정하는 문제입니다. 가까운 슬롯부터 배정하면 이동 경로가 교차해 대형이 엉킵니다. 이를 이분 그래프 최적 할당으로 정의하고 헝가리안 알고리즘을 직접 구현해 총 이동거리가 최소인 배치를 계산했습니다. 같은 알고리즘을 부대 ↔ 진형 선분 배정에도 재사용합니다.

Unity 2022.3URP DOTS / BurstJob System 헝가리안 알고리즘

CarDrive

운전 서바이벌 호러

밤길을 달리는 1인칭 운전 게임. 주행 중 귀신이 차체에 달라붙어 체력을 깎고, 플레이어는 앙크를 충전해 퇴치합니다. 한 손으로 운전하며 다른 손으로 싸웁니다.

핵심 문제

운전이 헐거우면 전투와 병행할 이유가 사라집니다. 그래서 차량을 WheelCollider 기반 물리로 구현하고, 토크 곡선·기어비·연료 소모는 CarData로 분리했습니다. 자동 변속과 시동(E키)까지 넣어 실제 자동차의 운전 감각을 살렸습니다. 귀신은 시동이 걸려 있을 때만 나타납니다.

Sandland

드론 지휘

1인칭으로 관제실을 이동하다 CRT 모니터 앞에 서면 제어 모드로 전환되고, 모니터 화면을 통해 정찰 드론 편대를 지휘합니다. 화면은 RenderTexture에 픽셀화·CRT 셰이더를 적용해 출력합니다.

핵심 문제

드론 편대가 대형(Line / Circle / V / Diamond)을 유지하며 NavMesh 위를 비행해야 했습니다. 어떤 드론을 어떤 대형 슬롯에 배정할지가 문제였고, RTXX와 동일하게 헝가리안 알고리즘으로 최적 배정을 계산했습니다. 카메라·수송·공격·호위·방어 드론이 역할별 상태 머신에 따라 동작합니다.

0MOJEON

부머 슈터

3D 공간에 2D 빌보드 스프라이트 적이 배치되는 레트로 FPS. 픽셀화, 색상 팔레트 양자화 렌더러 피처로 90년대 FPS의 화면을 재현했습니다.

핵심 문제

부머 슈터의 재미는 총이 아니라 이동에서 나옵니다. 그래서 이동 처리에 가장 공을 들였습니다. Rigidbody 가속/마찰 기반 이동에 공중 대시, 벽 슬라이딩, 계단 자동 오르기를 더해 속도가 끊기지 않게 했습니다.

MX4

청소 시뮬레이터 Logitech 공식 협업

마우스를 드래그해 3D 오브젝트 표면의 얼룩을 물로 닦아내는 게임. Logitech Action Ring으로 도구를 전환하고, MX Master 4 햅틱으로 피드백을 전달합니다.

핵심 문제

얼룩의 제거 진행도를 매 프레임 계산해야 했습니다. 얼룩을 텍스처가 아니라 UV 공간의 RenderTexture 마스크로 두고 HLSL 브러시 셰이더가 직접 그려 넣습니다. 진행도는 마스크를 CPU로 읽는 대신 밉맵을 생성해 최하위 1×1 밉이 전체 평균이 되는 성질로 구했습니다. 데스크톱에서는 AsyncGPUReadback으로 비동기 처리하고, 이를 지원하지 않는 WebGL에서는 셰이더로 1×1까지 blit한 뒤 동기 리드백하는 폴백 경로를 뒀습니다.

Unity 6HLSL RenderTextureAsyncGPUReadback WebGL.NET 8

SCPPJ

액션 어드벤처 팀 프로젝트

전투 · 잠입 · 단서 추론을 결합한 3D 액션 어드벤처. 팀 프로젝트지만 약 338개 스크립트를 유일한 프로그래머로서 전량 직접 작성했습니다. 참여한 작업 중 아키텍처 설계 비중이 가장 큽니다.

핵심 문제

기능이 늘수록 시스템 간 결합이 빠르게 증가했습니다. 혼자 전체 코드를 감당하려면 이걸 잡아야 했습니다. VContainer DI로 스코프(Root / Gameplay / Player / Combat / UI / Puzzle)를 분리해 조립하고, 시스템 간에는 직접 참조 대신 struct 이벤트 버스로 통신하게 했습니다. 갱신은 개별 Update() 대신 중앙 틱 매니저가 ITickable을 호출합니다.

Logitech

하드웨어 연동 · 2026년 7월 공식 협업

Logitech과 공식 협업으로 MX Master 4 · Action Ring 연동 작업을 진행했습니다. 게임 쪽(MX4)과 개발 도구 쪽(LogiForUnity), 두 갈래의 결과물이 나왔습니다.
